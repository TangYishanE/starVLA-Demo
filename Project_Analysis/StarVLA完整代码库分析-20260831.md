## 4. 核心包 `starVLA/` 深挖

### 4.1 模型层 `model/` —— 三层注册架构

**入口**：`starVLA/model/tools.py` 定义 `Registry` + `FRAMEWORK_REGISTRY` + `FrameworkTools`；`base_framework.py` 的 `build_framework(cfg)` 是唯一构建入口（自动扫描并 import 全部 framework 模块）。

**Framework 基类契约**（`baseframework(PreTrainedModel)`）—— 全库统一的 API 面：

| 方法 | 用途 |
|---|---|
| `forward(examples: List[dict])` | 训练前向（原始数据 dict 输入，无预处理） |
| `compute_loss(tag, batch, loss_scale)` | 训练损失（支持 `vla`/`vlm`/`cotrain` 多 tag） |
| `predict_action(examples)` | 推理路径（输出 `normalized_actions`） |
| `from_pretrained` | 从 checkpoint 加载（config + 归一化统计 + 权重） |

**Framework 注册表（27 个键，23 个框架 + 4 个别名）**：

| 家族 | 框架（注册名） | 说明 |
|---|---|---|
| **VLM4A**（16） | `QwenOFT`（MLP+L1）、`QwenGR00T`（DiT-B flow matching）、`QwenPI`/`QwenFM`、`QwenPI_v3`（LayerwiseFM cross-DiT）、`QwenFast`（离散 action token）、`QwenAdapter`、`QwenDual`、`QwenDiscreteDiffusion`（MaskGIT）、`EgoVLA`、`ABot_M0`、`CosmosGR00T`、`Gemma4GR00T`/`Gemma4PI`、`MiniCPMGR00T`/`MiniCPMPI`、`LangForce`、`InternVLA-M1`、`Pi0`/`PI0`、`Pi05`/`PI05` | 主战场；Qwen 系最全 |
| **VM4A**（2） | `ACT`（LeRobot ACTPolicy）、`DiffusionPolicy`（vendored DP，ResNet18+DDPM） | 从零训练的轻量 visuomotor 基线，走同一套数据/归一化/部署接口 |
| **WM4A**（6） | `WanOFT`/`WanPI`/`WanGR00T`、`CosmoPredict2OFT`/`CosmoPredict2PI`/`CosmoPredict2GR00T` | 世界模型当 backbone（视频生成 DiT 直接预测动作），见 docs/WM4A.md |

**Action Head 库**（`model/modules/action_model/`，14 个）：`MLP_ActionHeader`、`DiTActionHeader`（GR00T 系）、`fast_ActionHeader`、`LayerwiseFM_ActionHeader`、`LayerwiseDiscreteDiffusion_ActionHeader`、`OpenPI_ActionHead`、`EgoVLA_ActionHeader`、`AML_ActionHeader`、`VLA_AdapterHeader`、`spike_action_model_multitimestep`，外加 `flow_matching_head/`（action_encoder + cross_attention_dit）与 `DiT_modules/`（gaussian_diffusion 全家桶）两个子包。

**VLM 模块**（`model/modules/vlm/`，12 个）：QWen2_5 / QWen3 / QWen3_5（0.8B–9B）、Florence2、Gemma4、MiniCPM_V、Molmo2、VILA（含 vila_egovla）、CosmosReason2、OpenPIPaliGemma、vendored `openpi_transformers`（gemma + siglip，兼容 transformers 5.x）。另有 `world_model/`（Wan2、CosmoPredict2）、`dino_model/`、`projector/QFormer`。

> 设计要点：框架文件（如 `QwenGR00T.py`）可独立 `python xxx.py --config_yaml` 单跑做 smoke test；`--framework.name` 一行切换框架；action head 与 VLM 正交组合。

### 4.2 数据层 `dataloader/`

- **`lerobot_datasets.py`**：入口，返回**模型无关的原始 dict**（image / lang / action / state），无 tokenizer/图像编码等模型侧预处理。collate_fn 恒等。
- **`gr00t_lerobot/`**（源自 NVIDIA GR00T）：
  - `datasets.py`（2886 行）：`LeRobotSingleDataset`（分片/shuffle/缓存统计）+ `LeRobotMixtureDataset`（多数据集加权混合）；delta/relative action 统计计算
  - `data_config.py`（1097 行）：`BaseDataConfig` 抽象 + 15+ 具象配置（OXE Droid/Bridge/RT1、LIBERO 4in1、Franka、Fourier GR1、ArxX5…），每份定义 `modality_config()` + `transform()`
  - `registry.py`：**自动发现** `examples/*/train_files/data_registry/data_config.py` 并合并进 `ROBOT_TYPE_CONFIG_MAP` / `DATASET_NAMED_MIXTURES` / `ROBOT_TYPE_TO_EMBODIMENT_TAG` —— 这就是"新 benchmark 即插即用"的机制
  - `transform/`：base（帧采样）/ concat（多相机拼接）/ state_action / video（解码）
- **`vlm_datasets.py`**（737 行）+ `qwenvl_llavajson/`：多模态 VLM 数据（sharegpt4v 等 llava-json 格式，含 rope2d）
- **`umi_datasets.py`**：新增 UMI 人手示教数据（#442）
- **`modality.json`** 约定：每个 benchmark 用该文件声明 state/action 各维度（如 LIBERO 7 维 + pad/gripper）、video 键映射、annotation 键映射

### 4.3 训练层 `training/`

- **`train_starvla.py`**（528 行）：主训练器。原生 PyTorch + Accelerate + DeepSpeed（显式循环，无 trainer 封装黑盒）。要点：
  - `STARVLA_DISABLE_DEEPSPEED=1` 环境变量可整体关掉 DeepSpeed（**Windows 单卡路径**）
  - NPU 支持（torch_npu，ImportError 静默忽略）
  - 不保存 optimizer state（省显存/磁盘，resume 只 load 权重）
  - 冻结：`--trainer.freeze_modules "regex/name_list"`（`TrainerUtils.freeze_backbones`）
  - 分层 LR：`learning_rate: {base, qwen_vl_interface, action_model}` dict（`build_param_lr_groups`）
- **`train_starvla_cotrain.py`**：VLA+VLM 多目标共训（`loss_scale: {vla:1.0, vlm:0.1}`）
- **`train_starvlm.py` / `train_starvln.py`**：纯 VLM 训练 / VLM 归一化训练
- **`trainer_utils/`**：`config_tracker.py`（AccessTrackedConfig，防未定义键访问）、`monkey_patch.py`（510 行）、`overwatch.py`、`trainer_tools.py`（冻结/加载/参数统计/优化器分组）

### 4.4 配置系统

- 单一全局 config 对象（OmegaConf），顶层键：`framework` / `datasets` / `trainer` / `run_id` / `wandb_*`
- 命令行 `--framework.qwenvl.base_vlm Qwen/...` 等 dotlist 覆盖；checkpoint 内 `config.yaml` 与覆盖合并（`merge_config_overrides`，低优先级）
- DeepSpeed 配置：`config/deepseeds/{zero2,zero3}.yaml` 等 5 份
- 训练模板：`config/training/` 4 份（cotrain_libero / cotrain_oxe / adapter / discrete_diffusion ×2）

### 4.5 部署层 `deployment/`

- **`model_server/server_policy.py`**：共享 WebSocket 推理服务器（msgpack_numpy 协议）。wrapper 负责反归一化 + chunk_size 发现；handshake 发送 metadata（action_chunk_size / state_keys / action_keys）供客户端核对 train/test 一致性
- **`server_policy_gr00t_zmq.py`**：GR00T ZMQ 协议兼容服务器（pyzmq）
- **`tools/`**：`websocket_policy_server/client`、`zmq_policy_server`、`msgpack_numpy`、`debug_server_policy`、`image_tools`
- **`docker/`**：4 个 Dockerfile（server/train/robocasa）+ compose
- **`upload/push_model_to_hf.py`**：checkpoint 发布工具

**Eval 协议（全库统一）**：PolicyClient（WebSocket）→ `server_policy.py` → `Framework.predict_action`；每个 benchmark 自带 `model2{bench}_interface.py` 桥接（delta→abs、action ensembling、协议特化），模型服务器保持通用。

## 6. 数据流（一条链贯穿训练/评估/部署）

```
原始数据集(LeRobot v2.1) 
  → examples/*/train_files/data_registry/data_config.py（auto-discover，modality.json 声明维度）
  → gr00t_lerobot 数据集（分片+混合+统计计算）
  → dataloader 产出 raw dict {image: List[PIL], lang: str, action: [T,D], state: [..,S]}
  → framework.forward() / compute_loss()        （训练）
  → framework.predict_action() → normalized_actions [B,T,D]
  → server_policy.py 反归一化（dataset_statistics.json）→ WebSocket → 各 benchmark model2*_interface.py → 仿真/真机
```

**关键工件**：`dataset_statistics.json`（训练时生成，eval/部署反归一化必需，须与 checkpoint 同目录存放）。

## 8. 已知 Bug 与坑（本仓库实测/已验证）

1. 🔴 **RoboChallenge eval import bug**：`local_self_test.py:28`、`test_with_mock_server.py:41` 从 `examples.simBenchmarks.RoboChallenge_table30v2` import，实际路径是 `examples.realRobots.RoboChallenge_table30v2` → ModuleNotFoundError。修复两行 import 即可。
2. RoboChallenge 训练 YAML `action_type: delta_ee` 与数据实际 absolute ee_pose 不一致 → 训练前先跑 dataloader smoke 核对取值范围。
3. QwenOFT `include_state: false` 训练 + eval 发 state → 推理时 state token 被拼进 instruction（#355）；train/eval 的 state 设置必须一致。
4. 下载脚本默认全量数据集（RoboChallenge = 1TB）→ 永远加 `--only <task>`。
5. ALOHA 双臂转换器 NotImplementedError（仅单臂 UR5/ARX5/DOS-W1）。
6. Windows：`os.symlink` 需管理员/开发者模式；bash 脚本硬编码 `conda activate starVLA_dev` + 集群 `CUDA_HOME`；DeepSpeed 在 Windows 不可用 → `STARVLA_DISABLE_DEEPSPEED=1`。
7. QwenPI 老 checkpoint 兼容性：LIBERO 发布的 `Qwen3-VL-PI-LIBERO-4in1` 是历史 LayerwiseFM 语义，需 `config_override` 指定 legacy 模式（README §"Released Qwen3-PI LIBERO checkpoint compatibility"），勿改 checkpoint 内 config。
8. `qwen3.5` 的 flash-linear-attention 可能破坏旧 checkpoint 性能（requirements.txt 注释）。

## 11. 结论与下一步建议

1. **先同步**：`git pull upstream main`（落后 46 提交）或切换 `starVLA_dev` 再开始任何复现。
2. **复现优先级**（延续 20260830 评估）：LIBERO eval-only（~1 天）→ SimplerEnv/OXE 共训 → RoboCasa；realRobots 中仅 EgoVLA 可 eval-only。
3. **环境搭建**：本地 Windows 用 `STARVLA_DISABLE_DEEPSPEED=1` + accelerate 单卡 yaml + `python`（非 python3）；下载走 `HF_ENDPOINT=https://hf-mirror.com`。
4. **动手路线**：先跑 100-step 训练 smoke（验证 3 工件：checkpoints/steps_N_*.pt + dataset_statistics.json + config.yaml）→ 3-step eval（local_self_test → mock server → production）。
5. **研究切入点**：在 QwenGR00T/OFT 骨架上换/加 action head 或加 affordance 分支，是最符合"乐高式"设计、也最贴合 ECCV 2026 投稿路线的做法。
